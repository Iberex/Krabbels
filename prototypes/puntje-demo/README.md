# Puntje – animation demo

A Phaser 3 demo (Vite + plain JavaScript) that plays every animation of **Puntje**, the pencil character, from PNG sequences rendered in After Effects. There is one button per animation.

**Live demo:** https://iberex.github.io/puntje-demo/

## Quick start

```bash
npm install
npm run render -- ~/Downloads/Potlood.aep   # render all comps with After Effects (headless), then crop
npm run scan     # build public/assets/puntje/manifest.json from the frames on disk
npm run dev      # runs the scan again, then starts Vite on http://localhost:5173
```

Optional, to test the tracker link:

```bash
npm run ws-test  # fake tracker on ws://localhost:8765, sends a random animation every 4 s
```

## Folder structure

```
puntje-demo/
├─ index.html              page + HTML overlay (info label, controls, buttons)
├─ public/assets/puntje/
│  ├─ manifest.json        generated by `npm run scan`, do not edit by hand
│  ├─ crop.json            per-animation crop offsets, written by `npm run render`
│  ├─ 01_rust/01_rust_00000.png, 01_rust_00001.png, ...
│  └─ <animationName>/<animationName>_00000.png, ...
├─ scripts/
│  ├─ render-ae.js         aerender -> PNG -> floor removal -> per-animation crop
│  ├─ scan.js              writes manifest.json
│  └─ ws-test.js           test WebSocket server
└─ src/
   ├─ animations.js        animation list: keys, English labels, loop/one-shot, hotkeys, tracker events
   ├─ main.js              Phaser scene, state machine, UI wiring
   ├─ tracking.js          Femto Bolt WebSocket stub
   └─ style.css            button and overlay styling
```

## Adding new renders

### Option A: render straight from the After Effects project

```bash
npm run render -- /path/to/Potlood.aep                 # all 19 comps
npm run render -- /path/to/Potlood.aep 11_springen     # only these comps
npm run scan                                           # then reload the page
```

This uses After Effects' `aerender` CLI in the background. It does not touch a project that is open in the After Effects app. For each comp named in `src/animations.js` it:

1. renders a TIFF sequence with alpha and converts it to PNG;
2. removes the light-grey floor that is in the comps. Plain floor becomes transparent, and Puntje's shadow on the floor becomes a soft transparent shadow. Coloured pixels on the floor, such as the eraser chip, are kept;
3. crops each animation to its own bounding box and writes the offset to `crop.json`.

The demo uses those offsets to put the comp's anchor point (horizontal centre, floor line) on the same screen spot for every animation. Without this step, the full 1920×1080 frames would need about 12 GB of GPU memory. With it they need about 1.7 GB. `npm run render -- --crop-only` re-runs steps 2–3 on frames already on disk.

### Option B: drop PNGs in by hand

1. Render the PNG sequence from After Effects with a transparent background.
2. Put it in `public/assets/puntje/<animationName>/`. Name the frames `<animationName>_00000.png`, `_00001.png`, and so on. Keep the comp size and anchor the same as the other animations.
3. Run `npm run scan` and reload the page.

The demo loads only what `manifest.json` lists. An animation without frames shows "(not rendered yet)" and its button is disabled. Empty (0-byte) files are skipped, so a render that is still running does not break the demo. A folder that is not in the table in `src/animations.js` still gets a button at the end of the list, and it plays as a one-shot.

To change a label, the loop/one-shot type or the order, edit `src/animations.js`.

## How the state machine works

Everything goes through one function: `playAnim(name)`. The buttons, the keyboard and the tracker all call it.

- **Start:** `18_binnenvliegen` (Fly in) plays once. Then `01_rust` (Idle) loops. If the intro is not rendered, Idle starts directly.
- **Loop animation:** keeps looping until another animation is chosen. Clicking the loop that is already playing does nothing, so it does not restart.
- **One-shot animation:** plays once (`repeat: 0`). On Phaser's `animationcomplete` event, `playAnim('01_rust')` runs. Clicking a one-shot again restarts it.
- **Force loop:** one-shots get `repeat: -1` too, so `animationcomplete` never fires. If you toggle it during a one-shot, the one-shot restarts from its current frame with the new repeat value.
- **No jumps:** there is one sprite with one fixed position and scale. Before each animation plays, its origin is set to the comp anchor point (centre, floor line) measured in that animation's crop box, using `crop.json`. Every animation's anchor therefore lands on the same pixel. Frames added by hand without `crop.json` use bottom centre (`0.5, 1`).
- **Speed** sets `sprite.anims.timeScale` (0.25×–2×). The value stays when the animation changes.
- **Pause** freezes the current frame. Choosing a new animation resumes playback.
- **No Idle rendered:** after a one-shot, Puntje holds its last frame.

### Controls

| Input | Action |
|---|---|
| `1`–`9`, `q` `w` `e` `r` `t` `y` `u` `i` `o` `p` | animations 1–19, in table order |
| `Space` | pause / resume |

You can also call `puntje.playAnim('11_springen')` in the browser console.

## Femto Bolt link (stub)

`src/tracking.js` connects to `ws://localhost:8765` and accepts these messages:

```json
{"anim": "11_springen"}
{"event": "jump"}
```

The event names are listed in `EVENTS` in `src/animations.js`. If no server is running, the demo retries every 3 s and keeps working. The browser itself may still log "WebSocket connection failed". The top-left label shows `tracker: connected / offline`.

## Note on memory

All frames are loaded up front as separate textures, about 1.7 GB of GPU memory after cropping. A laptop or desktop handles that fine. An iPad may not: Safari limits memory per tab. If it crashes there, pack each animation into a trimmed texture atlas or load animations on demand.

## Dev server note

`vite.config.js` serves `assets/puntje/*` straight from disk. Without this, Vite's cached list of public files can answer newly rendered frames with `index.html`.

## Deploy

Every push to `main` builds with Vite and publishes to GitHub Pages (`.github/workflows/deploy.yml`). After new renders: `npm run scan`, commit `public/assets/puntje/`, push.
